# Touch performance review, 21 October 2026

Boris requested an Opus 5.5 consultation at maximum effort. The completed
read-only CLI review reports `claude-opus-5-5`; it ran with `--effort max`.
It examined a sanitized source snapshot and the original phone traces.
The maintainer made and tested the changes. This was a review of that baseline,
not approval of the final implementation or a passing 60 fps result.

The useful findings and their disposition:

| Finding | Change or remaining work |
| --- | --- |
| The event loop adds a sleep even when a frame is already late. | Permit a zero timeout, recalculate the deadline after status work, and wake the existing LVGL timers when evdev reports input. |
| Animation and refresh timers use different periods. | Both now use 8 ms. Measured completion intervals remain the acceptance gate. |
| Status and telemetry compete with motion. | Status writes run at 10 Hz. Independent telemetry/discovery reads are spread across five phases; each source still samples once per second. Live scene rebuilding remains a separate defect. |
| Moving pages repeatedly draw their backgrounds and text. | Prepare viewport images at rest and suppress the covered live objects during page motion. |
| Sheets blend the whole screen and invalidate an unnecessarily large container. | Dim the underlay once, move an opaque card image within its actual travel band, and keep a separate target for outside taps. Live controls return at rest. |
| Pinch release rebuilds text and can briefly show the old size. | Small immutable documents prepare five layouts. Retain the preview until the selected layout and reading anchor are ready. Large/live documents still need incremental preparation. |
| Pinch start takes another snapshot of already-rendered content. | Copy the settled viewport when its scene, page, scroll and cache state match. Otherwise use LVGL's snapshot. Both paths count against the pixel-cache limit. |
| The custom image draw unit accepts more geometry than it implements. | Reject tiling and mismatched image areas; use Pixman's padded nearest-neighbour sampling for the supported transform. Unsupported tasks stay with LVGL. |
| Existing performance tests omit zoom-out, bottom sheets and startup latency. | Add both workloads and phone-local timing marks. Trace sheet presence and font size as well as position/scale, so the final sheet removal and text reflow remain in the measured sequence. Behavioral checks also cover a pinch interrupting inertial reading and outside taps above/below sheets. Gesture thresholds are included in the onset observations; they are not glass latency. |
| A long copy wall time does not by itself prove slow pixel copying. | Trace CPU time, context switches, damage bounds and telemetry/status work. CPU accounting is quantized to 10 ms on this kernel, so individual-frame CPU attribution remains coarse. |

A temporary normal-scheduler priority change to nice −10 did not improve the
reading workload and was reverted. No real-time scheduling, kernel reboot,
panel register changes or remote-access changes were made for that experiment.

Remaining work must target measured causes: cold sheet preparation, residual
copy/scheduling stalls, live updates, large-document reflow and physical touch.
The simpledrm copy completion is not a measured panel refresh. Keep the strict
failure result visible in [performance.md](performance.md), and preserve the
previous renderer and independent SSH while investigating.
